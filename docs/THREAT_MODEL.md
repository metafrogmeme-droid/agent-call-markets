# Threat model

> Hackathon demo on Solana devnet with test tokens only. Not a live market, not gambling, and not financial advice. Unaudited.

Each item below is handled in code and tests, or documented as a residual risk in the README. Items 1–8 come from `CLAUDE_BRIEF.md` §6; items 9–14 were added during planning.

**Status (25 Nov):** the core (M1), the on-chain call lifecycle (M2) and the parimutuel market (M3: vault, positions, buy, redeem) implement items 1, 2, 3, 5, 6, 9, 10 and 11. The Solana adapter, mainnet guard and CLI (M4) implement item 12 and the local key handling of item 7. The journal bridge (M5, draft PR) adds bridge-side protections for items 1 and 2. The record page (items 4, 8) comes in M6.

| # | Threat | Mitigation | Where tested |
|---|---|---|---|
| 1 | **Look-ahead / late sealing** | The commitment is on-chain before the market opens (`seal_slot < open slot`). Reveal happens in a later slot than the seal. Expiry must be at least `min_lead` away and at most `max_horizon`. Trading closes `trade_cutoff` before expiry. The bridge (M5) never seals a journal entry that is future-dated or older than the maximum entry age (900 s), so old entries can't be backfilled with hindsight. | core validation tests; program tests (M2); bridge planner tests (M5) |
| 2 | **Selective reveal** (agent hides losing calls) | An unrevealed call past `reveal_deadline` counts as a MISS in record maths, and its market never opens. A lost salt has the same effect. The bridge (M5) seals every eligible journal entry and reports each entry it leaves out, with the reason. It makes one attempt per entry and never quietly re-seals an edited one, so which calls were selected stays visible. | core record tests (M1b); bridge planner and executor tests (M5) |
| 3 | **Oracle manipulation / stale price** | Owner pinned to the Pyth Core receiver `rec5EK…` (`PYTH_RECEIVER_PROGRAM_ID`; any other owner, including the Pyth Core Compatible receiver, is rejected), PriceUpdateV2 discriminator, **full** Wormhole verification, feed id = committed feed id, `publish_time ∈ [expiry, expiry + W]` and not later than now, unique update covering expiry, `conf / price ≤ max_conf_bps`. Fail closed. Permissionless void after `expiry + void_after`. The adapter sends exactly one price account per settle and never posts updates itself. | core tests + settlement vectors; program instruction tests incl. every rejected owner (M2/M3); adapter tests against the SBF binary repeat the owner and one-update cases (M4) |
| 4 | **Agent betting on own calls / wash trading** | Same-key positions on an agent's own market are flagged publicly on the record page. The hit rate is unaffected by trading. The README says plainly that self-trading from other wallets can't be detected. | record tests (M1b, M6) |
| 5 | **Settlement griefing** | Settle is permissionless and accepts **exactly one price update per market**: afterwards the same update is rejected as a duplicate and any other update is rejected; the outcome never changes. Late settlement is possible while the unique update exists; after that, the void path applies. | core conformance + program tests (M3) |
| 6 | **Rounding and pool drain** | Integer floor maths with u128 products, pool totals ≤ u64, Σpayouts ≤ vault, dust < number of winners, exact refunds on VOID, one redeem per position, no redeem before settle or void, payouts only to the owner's own token account, vault authority = call PDA. | core fast-check + Rust proptest + shared pool vectors + program tests (M3) |
| 7 | **Key handling** | No keys in the repo. Throwaway devnet keypairs are generated locally into `.devnet/` (gitignored) by `acm keygen`: 0600, never overwritten, never printed. Key files readable by others are refused. Salts are written 0600 before the seal is sent and are never printed. gitleaks scans the full history and Semgrep runs secrets rules on every push and PR. CI never needs secrets: the smoke run's localnet keys live in the runner's temp directory only. | CI `security` job (from PR #0); CLI file tests (M4) |
| 8 | **Front-end** | Read-only by default: no wallet connection, no signing prompts, no third-party scripts, a CSP. Seals carry no free-text fields, so chain data can't inject markup. | review + build check (M6) |
| 9 | **Commitment copying / replay** | The agent key is in the preimage, and the reveal signer must equal `call.agent`. A domain tag plus version byte separate formats. | golden vectors + program tests |
| 10 | **Encoding ambiguity / salt brute force** | Fixed-width canonical encoding. A 32-byte CSPRNG salt (the call space is small, so the salt carries the hiding). The same vectors are checked in TS and Rust. | fast-check round-trip, vectors |
| 11 | **Settler picks a favourable update** (adversarial selection) | Settlement only accepts the **unique** update covering expiry, as Pyth defines it: `prev_publish_time < expiry ≤ publish_time`, plus W = 10 s. A settler cannot choose among several updates. Residual risk: if Pyth publishes no such update, the call can only be voided (refunds). | core + Rust settlement vectors; program tests (M2) |
| 12 | **Accidental mainnet use** | Fail closed, no override. Mainnet-beta and testnet genesis hashes are always refused. `devnet` needs the devnet genesis hash. `localnet` needs a loopback RPC host and a non-public genesis hash, so a tunnel to mainnet is still refused. The adapter can only be built through the guarded `connect`, and the guard runs again before every transaction. The CLI accepts only `--cluster devnet|localnet`. `Anchor.toml` has no mainnet cluster. pm-AMM uses the same program ID on mainnet, so this guard is mandatory. | guard unit tests; adapter tests (an endpoint that turns into mainnet gets nothing sent); CLI tests; localnet smoke (a local RPC claiming devnet is refused) (M4) |
| 13 | **Third-party program risk (pm-AMM path)** | The pm-AMM devnet program can be upgraded by a single key and is unaudited (self-declared). Pin the IDL version, check the program ID, and fail closed on unexpected account layouts. If the spike fails, use the parimutuel fallback. | spike (M2/M3) |
| 14 | **Supply chain** | Frozen lockfile, pnpm build-script allowlist, actions pinned to commit SHAs, pinned tool versions, minimal dependencies. | CI |
